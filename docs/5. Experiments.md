# 실험 기록

각 실험은 **가설 → 변경 사항 → 결과 → 해석 → 다음 실험** 순서로 기록한다. 평가 방식과 모델 구조는 `modeling.md`, 이 문서는 성능 변화와 개선 과정만 다룬다.

실제 실행 결과가 확인된 실험에만 번호를 부여한다. 기존 예정 Experiment 03·04는 실행 순서에 맞춰 아래 완료 실험으로 대체하고, 미실행 항목은 향후 실험 후보로 옮겼다. 현재 기록에서 확인되는 실행 결과는 Experiment 01~04이며, 별도 결과가 없는 피처 변경은 독립 실험으로 만들지 않았다.

## 공통 검증 조건

- 전체 Train 기간: 2013-01-01 ~ 2017-08-15 (3,008,016행)

  - 검증: 2017-07-31 ~ 2017-08-15 (28,512행)
- Experiment 03~04: 학습 시작일을 고정하고 학습 종료일을 늘리는 3-Fold 시계열 백테스트

- 평가 지표: RMSLE (낮을수록 좋음)
- 타깃 변환: `sales_log = log1p(sales)`로 학습하고, `np.expm1(np.maximum(pred_log, 0))`으로 복원한 뒤 원본 판매량 기준 RMSLE 계산
- 학습 중 평가 지표: 로그 타깃의 RMSE. 음수 로그 예측을 0으로 보정하므로 복원 후 RMSLE와 소폭 다를 수 있음
- 모델: LightGBM (`gbdt`, `learning_rate=0.05`, `num_leaves=31`, `min_child_samples=50`, `random_state=42`, Early Stopping 50)
- 3-Fold 실험은 Fold마다 새 모델을 생성한다. 평균 RMSLE는 Fold 점수의 산술평균이며, 표준편차는 `pandas.Series.std()` 기본값인 표본 표준편차다.
- 단일 Validation과 3-Fold 평균은 직접적인 개선율 비교 대상으로 삼지 않는다. Experiment 01~02와 비교할 때는 같은 기간인 Fold 3을 사용한다.
- 피처 변경 효과를 비교할 때 Fold, 모델 설정, Early Stopping 조건을 동일하게 유지한다. Best Iteration은 학습 결과에 따라 달라질 수 있다.
- 검증 점수와 Kaggle Public 점수는 구분한다. Public 점수만 반복 최적화하지 않는다.

## Experiment 01 — 초기 모델

### 목적 / 가설

- 이후 개선 효과를 비교하기 위한 기준 성능 확보
- 날짜·프로모션·Holiday 기본 피처로 첫 Baseline 구축
- 첫 Baseline의 목적은 최고 점수가 아니라 비교 기준 확보

### 설정 / 변경 사항

- n_estimators: 1000
- 사용 피처: 19개
  - 매장·상품군: `store_nbr`, `family` (범주형)
  - 날짜: `year`, `month`, `day`, `dayofweek`, `is_weekend`
  - 프로모션: `onpromotion`, `onpromotion_log`, `is_promotion`
  - Holiday: `has_national_event`, `event_christmas`, `event_new_year`, `event_carnival`, `event_mothers_day`, `event_independence_day`, `event_good_friday`, `event_labor_day`, `event_other`
- 제외 피처: `id`, `date`, `sales`, `sales_log`, `is_added_missing_date`, `holiday_count`, Holiday 문자열 범주형, `event_city_foundation` (당시 Train에서 전부 0)
- 나머지 모델 설정: 공통 조건 참고, `reg_alpha=0`, `reg_lambda=0`, 나머지는 당시 기본 설정
- Lag / Rolling 피처 없음, 하이퍼파라미터 탐색 없음

### 결과

- Best Iteration: 1,000 (Early Stopping 미발동)
- Valid RMSE (log): 0.446283
- Valid RMSLE: 0.446059
- Public RMSLE: — (제출하지 않음)

### 해석

- 최대 반복 횟수인 1,000회까지 Validation 손실이 계속 개선되고 있었다.
- 반복 횟수를 늘려 볼 가치가 있다고 판단했다.

### 다음 실험

- 다른 조건을 유지하고 n_estimators를 1,300으로 늘려 비교

## Experiment 02 — 트리 수 증가

### 가설

- 1,000회에서도 Validation 손실이 줄고 있었으므로, 트리 수를 늘리면 추가 학습으로 예측 오차가 줄어들 수 있다.

### 변경 사항

- 비교 대상: Experiment 01
- n_estimators: 1000 → 1300
- 다른 조건(19개 피처, learning rate, 트리 설정, Validation 구간)은 동일

### 결과

| 항목 | Exp 01 | Exp 02 |
| --- | --: | --: |
| n_estimators | 1,000 | 1,300 |
| Best Iteration | 1,000 | 1,300 |
| Valid RMSE (log) | 0.446283 | 0.440323 |
| **Valid RMSLE** | 0.446059 | **0.440020** |
| Early Stopping | 미발동 | 미발동 |

- Valid RMSLE 변화: **−0.006039, 약 1.35% 개선**
- Public RMSLE: **0.49044**
- 제출 당시 순위: **304위** (당시 1위 Public RMSLE 0.37165, 격차 0.11879)
- Validation과 Public 차이: 0.050420
- 제출 파일: 28,512행 × 2열(`id`, `sales`)
- Train 구간만으로 학습한 모델로 제출. Train + Validation 전체 재학습은 미진행

### 해석

- 반복 횟수를 늘리자 같은 Validation에서 성능이 개선되었다. 당시 이후 실험의 비교 기준으로 삼았다.
- 두 실험 모두 Early Stopping이 발동하지 않았으므로 1,300회가 최선이라고 단정할 수 없다.
- `store_nbr`, `family`가 가장 많이 사용됐고 날짜·프로모션 피처가 뒤를 이었다.
- `onpromotion_log`는 중요도 0이었다. 원본과 정보가 겹쳐 선택되지 않았을 가능성이 있지만, 원인이나 제거 효과는 별도 실험으로 확인해야 한다.
- Split Importance는 사용 빈도이며 성능 기여도의 증명이 아니다.
- 당시 Test에는 National 이벤트가 없었다. 다만 이벤트 피처가 0이어도 트리 경로에 영향을 주므로, “Test에서 거의 작동하지 않는다”는 기존 해석은 수정한다. Holiday 피처 유용성은 제거 실험으로 확인한다.
- Test의 Local 이벤트인 2017-08-24 Ambato는 매장 지역 정보와 연결해야 한다.
- Validation–Public 차이의 원인은 단정하지 않는다. 여러 시점의 16일 구간에서 성능 변동을 확인할 필요가 있었다.
- 당시 모델은 과거 판매량을 정답으로만 사용했다. 매장 메타데이터, 지역 Holiday, Lag / Rolling 등 빠진 정보의 효과를 확인하는 방향으로 진행했다.

## Experiment 03 — 매장·지역 Holiday 피처 반영 및 3-Fold 백테스트

### 가설

- 매장 메타데이터와 지역별 Holiday 정보가 매장 ID와 기존 이벤트 피처를 보완할 수 있다.
- 반복 횟수 상한을 늘리고 Early Stopping으로 학습을 종료하면 기존 1,300회 이후의 개선 가능성을 확인할 수 있다.
- 16일 검증을 여러 시점에 적용하면 단일 Validation에서 보이지 않는 구간별 성능 차이를 확인할 수 있다.

### 변경 사항

- 비교 대상: Experiment 02. 직접 점수 비교는 같은 기간인 Fold 3에서 수행
- 사용 피처: 19개 → 23개
  - 추가: `city`, `state`, `type`, `cluster`, `holiday_count`, `event_city_foundation`
  - 제외: `onpromotion_log`, `has_national_event`
- 매장 메타데이터 범주형 처리 및 지역 Holiday 매칭을 포함한 파이프라인 반영
- n_estimators: 1300 → 5000, Early Stopping 50 유지
- 마지막 16일 단일 검증 → 3-Fold 시계열 백테스트
- Lag / Rolling / EMA 없음
- 모델 설정: `max_depth=-1`, `min_split_gain=0.0`, `subsample=1.0`, `subsample_freq=0`, `colsample_bytree=1.0`, `reg_alpha=0`, `reg_lambda=0`, `importance_type="split"`, `n_jobs=-1`
- 전처리, Store Date Features, Holiday Store Matching, Feature Engineering, 전체 QC가 모두 OK로 출력됨
- 피처 구성과 반복 횟수가 함께 바뀌었으므로 개별 변경의 효과를 분리한 실험은 아님

### 해석

- 동일한 마지막 16일 구간에서 Experiment 02보다 개선되었다. 다만 증가한 반복 횟수와 피처 변경이 함께 반영된 결과이므로 매장 정보나 지역 Holiday만의 효과라고 할 수 없다.
- `onpromotion_log` 제거도 다른 변경과 함께 반영됐다. 중요도 0 피처 제거 단독 실험을 완료한 것으로 기록하지 않는다.
- 매장 메타데이터 네 컬럼이 모두 분할에 사용됐다. 실제 추가 기여는 별도 Ablation이 필요하다.
- 세 검증 구간의 점수는 0.412261~0.422125였다. 인접한 여름 구간의 결과이며 연중 모든 계절에 대한 안정성을 입증하지는 않는다.
- Fold마다 Best Iteration이 달랐다. 평균·중앙값·최근 Fold 값은 최종 학습 횟수 후보이며, 하나가 자동으로 최적값이 되는 것은 아니다.
- 평균 split은 정규화하지 않은 횟수의 평균이다. Fold별 트리 수가 다르므로 학습이 길었던 모델의 사용 횟수가 더 크게 반영될 수 있다.

## Experiment 04 — Lag Feature 추가

### 가설

- 매장 × 상품군별 과거 판매량을 입력하면 날짜·매장 정보만으로 설명하기 어려운 판매 수준을 반영할 수 있다.
- 같은 요일의 과거 판매량을 함께 제공하면 주간 패턴을 보완할 수 있다.

### 변경 사항

- 비교 대상: Experiment 03
- 기존 23개 피처에 `sales_lag_16`, `sales_lag_21`, `sales_lag_28` 추가 → 총 26개
- 매장 × 상품군별 날짜순 정렬 후 `groupby(["store_nbr", "family"], observed=True)["sales"].shift(lag)`로 생성
- 원본 `sales` 기준으로 계산하며 `sales_log`의 Lag가 아님
- 16일: 16일 일괄 예측에서 전체 예측 구간에 사용할 수 있는 최소 고정 Lag
- 21일 / 28일: 각각 3주 / 4주 전 같은 요일의 판매량. 최적값이 아니라 초기 가설에 따른 후보
- 전체 Train에서 Lag 생성 후 Fold 분리. 각 Validation이 16일이고 모든 Lag가 16 이상이므로 검증 행의 Lag는 해당 Fold의 학습 기간만 참조
- 매장 × 상품군별 키 중복 및 날짜 간격 1일 여부 검증
- 학습 초기 과거 기록 부족에 따른 Lag NaN은 그대로 유지. 기존 피처 및 Validation Lag에는 결측치를 허용하지 않음
- Fold, 모델 파라미터, n_estimators=5000, Early Stopping 50은 Experiment 03과 동일

54개 매장 × 33개 상품군 = 1,782개 시계열에서 예상한 초기 결측치와 실제 출력이 일치했다.

| `sales_lag_21` | 1,782 × 21 = 37,422 | 37,422 |
| `sales_lag_28` | 1,782 × 28 = 49,896 | 49,896 |

- Lag QC: OK
- Fold 데이터 열 수: 28 → 31, 모델 입력 피처 수: 23 → 26
- 각 Validation 입력: (28,512, 26), 행 수 유지

### 해석

- 같은 설정의 세 Fold에서 모두 개선돼, 이번 백테스트에서는 Lag 세 개를 함께 추가한 효과가 일관되게 나타났다.
- 평균 RMSLE는 약 3.26%, 직전 최고와 같은 기간인 Fold 3은 약 1.49% 개선됐다.
- Fold 1의 0.396964는 다른 기간의 점수이므로 이전 Fold 3 점수와 직접 개선율을 계산하지 않는다.
- 표준편차는 증가했다. 평균 성능 개선과 구간별 점수 편차 감소는 별개의 문제다.
- 세 Fold 모두 더 적은 트리로 더 낮은 오차에 도달했다. 다만 실제 실행 시간은 별도 측정하지 않았으므로 학습 시간 단축까지 단정하지 않는다.
- 세 Lag가 모두 상위 분할 피처로 사용됐다. 이것만으로 Lag별 개별 기여나 16일 Lag의 우월성을 확정할 수는 없다.
- 기존 피처의 split 감소에는 트리 수 감소도 영향을 준다. 이를 곧바로 기존 피처의 성능 기여 감소로 해석하지 않는다.
- 초기 Lag 결측치는 관측 가능한 과거 기록이 없다는 의미다. 실제 판매량 0과 구분해 유지했다.
- Experiment 04를 다음 피처 추가 실험의 비교 기준으로 삼는다.

- Test 원래 순서 복원, 범주형 기준 통일, Test Lag 결측치 검사
- 전체 Train으로 학습 → Test 예측 → `sample_submission.csv`의 id에 맞춰 병합 → CSV 저장
- Train 초기 Lag NaN은 허용하고 Test 입력 결측치는 금지

- Validation 없는 전체 학습에서는 Early Stopping 대신 정한 반복 횟수로 학습한다.

## 향후 실험 후보

미실행 실험에는 번호를 미리 부여하지 않는다. 실제 실행 순서대로 다음 Experiment ID를 붙인다.

| 우선순위 | 실험 | 목적 / 비교 방식 |
| --: | --- | --- |
| 1 | Rolling mean 추가 | Lag 모델 대비 과거 구간의 평균 판매 수준 보완 |
| 2 | EMA 추가 | 최근 관측값에 더 높은 가중치를 준 판매 수준 반영 |
| 3 | Rolling min / Rolling std 추가 | 최저 판매 수준 및 변동성 효과를 각각 확인 |
| 4 | 개별 Lag 및 피처 묶음 Ablation | Holiday, type, cluster 등 제거 대상만 바꿔 각각 비교 |

- Rolling / EMA도 현재 16일 일괄 예측 조건에 맞춰 판매량을 먼저 충분히 이동시킨 후 계산한다.
- Rolling은 계산 구간을 묶는 방식이며, Rolling mean은 평균, Rolling min은 최솟값, Rolling std는 표준편차다.
- 지역 Holiday + 매장 메타데이터 반영과 3-Fold 백테스트는 이미 Experiment 03에 반영됐다. 앞으로는 미완료 작업으로 반복 기재하지 않고, 필요하면 해당 구성의 개별 효과를 검증한다.
- 모든 추가 실험에서 가설·변경·결과·해석을 남기고, 개선되지 않은 결과도 기록한다.

### 1. 외부 데이터 전처리 결과와 모델 입력 점검

Day12에서는 외부 데이터의 EDA와 결측 보완 규칙을 정리했다. Day13에서는 이를 모델 입력 데이터와 연결하면서 행 수와 결측을 확인했다.

| 항목 | 확인한 내용 |
|---|---|
| Oil 일별 데이터 | 날짜 확장 후 **1,688행** |
| Oil 보완 대상 | **525개 결측값 보완**, 최종 결측 0개 |
| Transactions 원본 | **83,488행** |
| Transactions 추가 행 | **324행** |
| Transactions 전처리 결과 | **83,812행** |
| 외부 데이터 cutoff | 기존 실험 구성에서 **2017-08-15** |
| Train | **3,008,016행** |
| Test | **28,512행** |

- Transactions의 324행 보완은 기존에 정한 12월 25일 216행, 2016년 1월 1·3일 총 108행을 반영한 결과다.
- **외부 데이터 자체의 결측 0개**와 **Train/Test 병합 후 결측 0개**는 서로 다른 검증 항목이다.
- 특히 `transactions.csv`가 2017-08-15까지만 존재하므로 Test 당일 `transactions` 값은 직접 입력할 수 없다. 이는 전처리 실패가 아니라 **미래 거래 건수를 관측할 수 없는 조건**이다.
- 기존 병합 단계에서 Transactions 결측이 발견되었다는 사실도 확인했다. 원본/보완 테이블의 QC가 통과했다고 모델 입력까지 자동으로 완성되는 것은 아니다.

### 2. 외부 피처 5개 실험 구성 — 각각 독립적인 Ablation 방식

**기준 모델:** Payday Baseline 29개 피처, LightGBM, `n_estimators=8000`, Early Stopping 150, 16일 × 3-Fold Rolling Validation.

| Fold | 기간 | 기존 Baseline RMSLE |
|---|---|---:|
| Fold 1 | 2017-06-29 ~ 2017-07-14 | 0.382044 |
| Fold 2 | 2017-07-15 ~ 2017-07-30 | 0.405838 |
| Fold 3 | 2017-07-31 ~ 2017-08-15 | 0.394152 |
| **평균** | | **0.394011** |

| 실험 | 추가 피처 | 추가 개수 | 총 피처 |
|---|---|---:|---:|
| `transactions_lag` | `transactions_lag_16`, `_21`, `_28` | 3 | 32 |
| `transactions_rolling` | `transactions_rolling_mean_16_7`, `_16_14`, `_16_28` | 3 | 32 |
| `oil_raw` | `dcoilwtico` | 1 | 30 |
| `oil_rolling_mean` | `oil_rolling_mean_7` | 1 | 30 |
| `oil_diff` | `oil_diff_7` | 1 | 30 |

- 각 실험은 **29개 Payday Baseline에 해당 피처만 추가**하며, 외부 피처 5종을 한 번에 섞는 방식이 아니다.
- Baseline은 새로 학습하지 않고 **이전에 저장한 Fold별 점수**를 참조했다.
- 실험마다 세 Fold를 학습하므로 총 학습 모델 수는 **15개**다.
- Transactions Lag는 날짜×매장 단위 거래량을 기준으로 16·21·28일 이전 값을 사용한다.
- Transactions Rolling은 16일 Shift를 먼저 적용한 다음 7·14·28일 평균을 계산한다. **16일 예측 구간의 미래 거래량을 직접 사용하지 않도록 설계**했다.
- Oil Raw는 날짜별 `dcoilwtico`, Oil Rolling은 7일 이동평균, Oil Diff는 7일 차이 피처를 검토한다.

**실험 점수 기록:** 이 회고 작성에 제공된 자료에서는 5개 실험 각각의 **실제 Fold별 RMSLE 로그가 확인되지 않는다.** 따라서 임의의 점수·순위를 만들지 않고, 확정된 피처 구성과 선택 결과만 남긴다. 구체적인 수치는 해당 실행 로그 또는 `score_summary.csv`를 기준으로 보완할 항목이다.

### 3. 피처 생성 및 누수 방지 점검

| 점검 항목 | 확인·설계 내용 |
|---|---|
| Train / Validation | 시간 순서에 따라 16일 단위로 분리 |
| Sales Lag | `sales_lag_16/21/28` 유지 |
| Transactions Lag | 16일 이상 과거 거래량만 참조 |
| Transactions Rolling | `shift(16)` 이후 이동평균 계산 |
| 매장×상품군 연속성 | 날짜가 하루씩 이어지는지 확인하는 QC 적용 |
| 범주형 입력 | Train에서 정한 범주를 Validation에 공통 적용 |
| 초기 Lag 결측 | 필요한 과거 관측 기간이 부족해 생기는 결측과 비정상 결측 구분 |
| Oil | 날짜별 값과 보간 값의 가용 시점 확인 필요 |

- 같은 날 매장의 Transactions나 Sales를 가져오는 것과 **16일 전부터의 과거 정보로 피처를 만드는 것**은 다르다.
- Train에서 계산할 수 있는 피처라도, 해당 Fold의 예측 시작일에 **실제로 알 수 있는 값인지**를 확인해야 한다.
- QC는 누락 컬럼, 중복 키, 비연속 날짜, 생성 피처 결측을 발견하는 장치다. **모든 미래 정보 누수가 제거되었다는 형식적 증명은 아니다.**

### 4. Oil Raw 베이스라인 확정 — 29개 → 30개

외부 피처 실험 이후 **기존 Payday Baseline 29개 + Oil Raw `dcoilwtico` 1개**를 제출 기준 모델로 선택했다.

| 항목 | 최종 선택 |
|---|---|
| 기준 모델 | Payday Baseline |
| 새로 추가한 피처 | `dcoilwtico` |
| 총 피처 수 | **30개** |
| 모델 | LightGBM Regressor (`gbdt`) |
| Target | `log1p(sales)` |
| Learning rate | 0.05 |
| Num leaves | 31 |
| Max estimators | 8,000 |
| Early stopping | 150 |
| 최종 Train 기간 | 2013-01-01 ~ 2017-08-15 |
| Test 기간 | 2017-08-16 ~ 2017-08-31 |

- 기존 Payday·Sales Lag·캘린더·공휴일·매장 관련 피처의 구성은 유지했다.
- Oil Raw를 넣되, **Transactions 파생 피처와 Oil Rolling/Diff는 이번 확정 베이스라인에 포함하지 않았다.**
- 제출 코드는 3-Fold의 Best Iteration을 참고해 최종 반복 횟수를 정하고, 전체 Train 데이터로 학습하여 Test 28,512행을 예측하는 구조로 준비했다.
- **새 베이스라인의 정확한 3-Fold 평균 RMSLE와 Public Leaderboard 점수는 현재 제공된 자료만으로 확인되지 않는다.** 기존 29개 Baseline의 0.394011과 혼동하지 않는다.

### 5. Kaggle 제출 코드 작성과 Oil 결측 오류

제출용 `final_submission.py`를 실행하면서 다음 오류가 발생했다.

```text
ValueError: Oil Raw(dcoilwtico)에 결측/무한대가 있습니다.
기존 oil 전처리를 확인하세요.
```

- 해당 오류는 모델의 성능 문제가 아니라 **모델 학습 전에 Oil 입력 QC에서 중단**되었다는 뜻이다.
- 오류 메시지만으로는 **Train의 결측인지 Test의 결측인지 바로 알 수 없었다.**
- 기존 파이프라인에서 외부 데이터 cutoff를 8월 15일로 설정한 만큼, Test 날짜의 유가가 병합되지 않았을 가능성을 점검했다.
- 초기에는 미래 Test 유가를 알 수 없다고 가정하고 **8월 15일의 마지막 유가로 16일을 고정**하는 수정안을 작성했다.
- 그러나 원본 `oil.csv`에는 **8월 16~31일의 날짜별 유가가 포함**되어 있으므로, 기존 Oil Raw 실험과 제출의 입력 방식이 달라지는 문제를 발견했다.

### 6. Oil Test 전처리 수정 — 마지막 값 고정에서 날짜별 Oil로 변경

| 항목 | 초기 제출 수정안 | 최종 수정 방향 |
|---|---|---|
| Train Oil | 날짜별 값 | 날짜별 값 |
| Test Oil | 8/15 마지막 값으로 16일 고정 | **Test 날짜별 Oil 값** |
| Test Oil 결측 | 마지막 값으로 대체 | 원본 Oil 날짜 확장·보간 처리 결과를 사용 |
| 3-Fold 비교 | 검증 기간의 Oil을 고정하면 기존 실험과 조건이 달라짐 | **기존 Oil Raw 실험과 동일한 날짜별 값 방식** |

- Oil은 Transactions와 다르게 **원본 파일이 Test 기간의 날짜별 값까지 포함**한다.
- 따라서 Train/Test 모두 **동일한 날짜별 Oil 병합 및 일별 날짜 복원·보간** 절차를 적용하는 방향으로 코드를 수정했다.
- 이때 *파일에 사후적으로 수록된 미래 날짜의 실제 Oil 값*과 *실제 운영 시점에 미리 관측할 수 있는 값*은 별개다. 대회 제출 데이터로 제공되는 값을 사용하는 방식과 현실적인 사전 예측 시나리오를 구분했다.
- **수정 코드는 작성했지만, 수정 이후 실행 성공·`submission.csv` 생성·Kaggle 점수 확인까지 이 대화에서 검증된 것은 아니다.**

## 판단 / 배운 점

### 1. 외부 데이터의 원본 범위와 모델 입력 범위를 각각 확인해야 한다

- 전처리된 Oil 데이터의 결측이 0개여도 Test에 날짜별로 제대로 연결되지 않으면 모델 입력에는 결측이 남는다.
- 원본 파일에 데이터가 있는지, 파이프라인에서 cutoff로 제거했는지, Train과 Test 양쪽에 병합했는지를 **서로 다른 단계**로 확인해야 한다.

### 2. 동일한 검증 조건에서 비교해야 피처 실험 결과를 해석할 수 있다

- Oil Raw를 날짜별 값으로 검증해 놓고, 제출에서는 8월 15일 값으로 고정하면 모델에 들어가는 정보가 달라진다.
- **베이스라인 피처 구성뿐 아니라 결측 처리, 시간 범위, 데이터 가용성 가정까지 같은 조건**이어야 검증 점수와 제출 결과를 비교하기 좋다.

### 3. Transactions와 Oil은 예측 기간의 가용성이 다르다

- Transactions 원본은 Test 기간의 당일 거래량이 없으므로 **과거값 기반 Lag·Rolling**으로 접근해야 한다.
- Oil 원본은 대회 파일에 Test 날짜별 값이 포함되어 있으므로 **이번 Kaggle 제출에서는 날짜별 Raw 값을 활용**하는 방식으로 정했다.
- 다만 실제 서비스에서 16일을 미리 예측할 때에도 같은 Oil 값을 사용할 수 있다는 뜻은 아니다.

### 4. 오류 메시지가 말해 주는 사실과 원인에 대한 가설을 구분한다

- `dcoilwtico` 결측 오류는 **어딘가에 결측/무한대가 있다**는 사실을 알려줄 뿐이다.
- “Test Oil이 없어서 발생했다”는 것은 추가 확인이 필요한 가설이며, Train/Test별 결측 개수와 누락 날짜를 출력해야 원인을 확정할 수 있다.

### 느낀 점

- Day12에는 외부 데이터 자체를 이해하고 전처리하는 데 집중했다면, Day13에는 **전처리된 데이터를 실제 모델과 Kaggle 제출에 일관되게 연결하는 과정**을 경험했다.
- 모델 피처를 하나 추가하는 작업도 실제로는 Train/Test의 날짜 범위, 결측 처리, 검증 조건을 함께 살펴야 한다.
- Oil 값을 단순히 마지막 값으로 고정한 수정안을 다시 살펴보면서 **에러를 없애는 것과 올바른 입력을 만드는 것은 다르다**는 점을 배웠다.
- **한 줄 정리: 새 베이스라인은 단순히 피처 30개의 목록이 아니라, 동일한 전처리·검증·제출 조건까지 포함한 전체 파이프라인이다.**

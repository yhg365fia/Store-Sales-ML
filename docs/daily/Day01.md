  - `train`/`test` 로드, 기본 구조 확인 (`shape`, `head`, `info`, `isnull`, `describe`, `nunique`)

  - 누적 판매량 상위 4개 매장, 상위 4개/8개 상품군의 시계열 비교

## 판단 / 배운 점
**데이터 이해**
- 한 행은 **날짜 × 매장 × 상품군의 판매량**이고, 매장 × 상품군마다 시계열이 따로 있는 **패널 시계열**
- `sales`: 평균 약 358, 중앙값 11, 25% 지점 0 → 0과 낮은 값에 몰려 있고 오른쪽 꼬리가 매우 긴 분포
- `onpromotion`: 광고 횟수가 아니라 **프로모션 중인 개별 상품 수**, 약 79.6%가 0
- 전체 판매량은 장기 상승 trend와 반복 패턴이 있고, 특정 날짜에 거의 0으로 급락 → 휴일/이벤트 가설
- 상위 매장·상품군도 전체 시계열과 비슷하게 움직임 → **개별 특성보다 공통 시간 패턴이 강해 보임** (상위 일부만 본 것이라 확정은 아님)

**EDA 방법**
- 극단값 때문에 그래프가 눌리면 범위를 잘라 확대해서 본다 (삭제가 아님)
- 평균과 중앙값 차이가 크면 일부 큰 값이 평균을 끌어올렸는지 의심한다
- 산점도에서 프로모션과 판매량이 같이 커져도 인과로 단정하지 않는다 (원래 규모가 큰 상품군일 수 있음)
- 54개 매장, 33개 상품군을 전부 보기보다 전체 규모를 먼저 보고 대표 그룹을 골라 깊게 본다

**모델링 아이디어**
- 상품군을 식품/신선식품/생활용품 같은 거시적 성격으로 묶는 feature
- 성능이 나쁜 상품군은 EDA로 돌아와 전용 feature를 추가하고 ablation으로 검증
- 별도 모델이 아니라 한 모델 안에서 공통 시간 feature와 상품군 정보를 함께 줄 수도 있음

**느낀 점**
- Kaggle과 EDA를 오랜만에 하고 아직 미숙해서, 전체 구조나 기초 의미를 여러 번 다시 물어봤다.
- 그래도 설명을 들으면 이해가 빠르고, 추가 코드 이해는 따로 필요하지 않았다. 덕분에 코드 자체보다 Kaggle과 프로젝트 전 과정을 거시적으로 보면서 EDA를 진행할 수 있었다.
- 저번에는 시키는 대로 하는 식이었다면, 이번에는 **왜 하는지, 나중에 어떻게 활용할지, 무엇이 중요한지**를 직접 판단하고 설계했다. EDA를 목적에 맞게 주도적으로 수행했다는 점에서 Kaggle/ML 실력이 조금 는 것 같다.
- 한 줄 정리: **EDA는 데이터를 구경하는 단계가 아니라 모델링 가설을 만드는 단계**

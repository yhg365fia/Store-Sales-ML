## 판단 / 배운 점

### 매장 ID와 메타데이터

- `store_nbr`는 **매장을 구분하는 고유 ID**이며, 번호가 크다고 매장 규모나 판매량이 큰 것이 아니다.
- 분할 횟수 기준 Feature Importance가 높다는 것은 모델이 매장 정보를 자주 사용했다는 뜻이지, 그 수치 자체가 성능 기여량을 나타내는 것은 아니다.
- 매장 ID가 중요하므로 메타데이터도 도움이 될 수 있다는 가설을 세웠다.
- 다만 **매장 ID가 중요하다고 메타데이터의 추가 효과까지 크다고 단정할 수는 없다.** 기존 모델이 매장 ID만으로 매장별 차이를 상당 부분 학습했을 수 있다.
- 메타데이터는 개별 매장을 구분하는 것에서 더 나아가, 여러 매장이 공유하는 특성을 표현한다.
  - `city`, `state`: 어디에 있는 매장인가
  - `type`: 어떤 유형의 매장인가
  - `cluster`: 어떤 매장들과 유사한가
- 특히 `city`, `state`는 지역적 특성을 표현하는 동시에 Regional / Local Holiday를 연결하는 기준이 된다.

### 도시·주별 매장 분포

- 54개 매장이 **22개 도시, 16개 주**에 분포했다.
- 도시별로는 Quito 18개, Guayaquil 8개로, 두 도시에 전체 매장의 약 **48.1%**가 모여 있었다.
- 주별로는 Pichincha 19개, Guayas 11개로, 두 주에 약 **55.6%**가 집중되어 있었다.
- 따라서 지역별 매장 수는 균등하지 않고 일부 지역에 집중되어 있다고 판단했다.
- 하지만 **매장 수가 많다는 것과 매장당 판매량이 높거나 판매 패턴이 같다는 것은 다르다.**
- 이번 집계는 지역별 매장 구성을 확인한 것이며, 지역별 판매 차이까지 검증한 것은 아니다.
- Ambato에는 매장이 2개 있으므로, 앞서 확인한 `2017-08-24`의 Local 이벤트는 해당 도시의 두 매장에 적용할 대상이다.
- 실제 매장 번호 확인과 Holiday 연결은 다음 작업으로 남겼다.

### type별 매장 수

- `type`별 매장 수는 D 18개, C 15개, A 9개, B 8개, E 4개였다.
- 완전히 균등하지는 않지만 **모든 유형에 여러 매장이 존재**했다.
- 따라서 같은 유형에 속한 매장들의 공통 특성을 모델에 알려주면 도움이 될 것이라고 판단했다.
- 매장 ID가 개별 매장을 구분한다면, `type`은 여러 매장을 같은 범주로 묶어 주는 정보다.
- 다만 매장 수 분포만으로 같은 타입의 판매 패턴이 실제로 비슷하다고 확정할 수는 없다.
- **공통 특성을 학습하는 데 도움이 될 것이라는 가설을 세우고, 실제 효과는 재학습으로 확인**하기로 했다.

### 작은 클러스터의 의미

- 54개 매장이 17개 클러스터에 속하며, 클러스터당 매장 수는 1~7개였다.
- 그중 매장이 1~2개뿐인 클러스터가 7개 있어, **이렇게 작은 그룹이 매장 ID에 비해 추가 정보를 제공할 수 있는지** 의문을 가졌다.
- 특히 매장이 하나인 클러스터는 여러 매장 사이의 공통 특성을 전달하기 어려울 수 있다고 생각했다.
- 하지만 **그룹에 속한 매장 수가 적다고 학습 행 자체가 적다는 뜻은 아니다.** 각 매장에는 여러 날짜와 상품군의 판매 기록이 존재한다.
- 따라서 작은 그룹이라는 이유만으로 피처를 제거하기보다, 기존 정보에 비해 어떤 추가 효과가 있는지 검증하기로 했다.
- `cluster`는 숫자로 저장되어 있지만 크기나 순서를 의미하지 않는 그룹 번호이므로 범주형으로 다룬다.

### type × cluster 관계

- 개별 분포를 확인한 뒤 교차표를 보니, **17개 클러스터 중 16개가 하나의 타입으로만 구성**되어 있었다.
- 처음에는 “대부분 같은 타입이 같은 클러스터네”라고 생각했지만, 정확히는 **같은 클러스터에 속한 매장들이 대부분 같은 타입**이라는 관계였다.
- 반대로 하나의 타입은 여러 클러스터에 걸쳐 있었다.
- 따라서 `cluster`가 타입 내부에서 더 세부적인 구분을 제공할 가능성이 있다고 봤다.
- 다만 클러스터 10은 B 1개, D 1개, E 4개로 구성되어 있어 완전한 상하 관계는 아니었다.
- **정보가 많이 겹친다는 것과 완전히 같은 정보라는 것은 다르다.**
- 우선 두 컬럼을 함께 활용하고, 이후 Ablation으로 각각의 추가 효과를 확인하기로 했다.
- 피처를 추가할 때는 컬럼이 하나 더 생긴다는 사실보다 **기존 피처에 비해 무엇을 더 알려주는지**를 생각해야 한다는 점을 배웠다.

### 전처리 결과 확인

- Train은 `2013-01-01 ~ 2017-07-30`, Validation은 `2017-07-31 ~ 2017-08-15`, Test는 `2017-08-16 ~ 2017-08-31`로 구성되어 있었다.
- Validation과 Test를 각각 **16일**로 맞춘 시간순 분리를 확인했다.
- 크리스마스 보완 행 7,128개를 포함한 Train은 2,979,504행이며, Validation과 Test는 각각 28,512행이었다.
- 보완 후 전체 날짜 범위에서 누락 날짜가 없음을 확인했다. 다만 추가한 크리스마스 판매량 0은 실제 관측값이 아니라 휴점일로 해석한 가정이다.
- Train의 판매량 왜도는 약 7.402에서 `log1p` 변환 후 약 0.415로 줄었다.
- **로그 변환으로 큰 값의 상대적 크기가 줄어들면서 오른쪽으로 치우친 분포가 완화되었다.**
- Train / Validation의 전체 결측치와 전체 행 중복은 0개였다.
- 전체 행 중복이 없다는 것과 `date × store_nbr × family` 키가 중복되지 않는다는 것은 별개의 검증이라는 점도 구분했다.

### 매장 정보 병합과 검증

- 판매 데이터에는 같은 매장이 여러 날짜·상품군에 반복되고, `stores.csv`에는 매장별 정보가 한 행씩 연결되어야 한다.
- 따라서 `store_nbr` 기준 `left merge`를 사용하고, `validate="many_to_one"`으로 병합 관계를 검증하도록 했다.
- 병합 후 Train / Validation / Test에서 `city`, `state`, `type`, `cluster`의 결측치가 모두 0개였고, 결측 발생 매장도 없었다.
- 이를 통해 **판매 데이터의 매장 번호에 대응하는 메타데이터가 누락 없이 연결되었음**을 확인했다.
- 기존 전처리 로그의 Train 8열·Test 6열은 매장 컬럼을 포함한 최종 구조가 아니므로, 병합 후 검증 결과와 구분해서 해석했다.
- **병합이 끝났다고 모델 입력 준비까지 끝난 것은 아니다.** 새 컬럼의 자료형·범주를 정리하고 모델 입력 피처 목록도 수정해야 한다.
- 오늘은 병합까지 반영했고, 범주형 변환과 지역 Holiday 연결은 다음 작업으로 남겼다.

### 코드 구조와 실험 순서

- `merge_holiday_features()`의 파일 위치를 바꿔도, 필요한 Holiday 피처가 먼저 생성되어야 한다는 실행 순서는 변하지 않는다.
- 함수가 어느 파일에 있는지와 실제로 언제 실행해야 하는지를 구분해야 한다.
- 다음에는 전처리와 매장·지역 피처 구성을 먼저 완성한 뒤, **기존 검증 조건과 모델 설정을 유지해 재학습**하기로 했다.
- 여러 피처를 함께 추가하면 전체 변경 효과는 확인할 수 있지만, 개별 피처의 기여도까지 구분할 수는 없다.
- 이후 같은 기준 모델에서 `type`, `cluster`, Holiday 묶음 등을 각각 제거하는 Ablation으로 추가 효과를 확인한다.
- 실험 번호는 실제 실행 순서대로 붙이고, 아직 실행하지 않은 실험은 예정 항목으로 구분한다.

### 느낀 점

- Day05가 첫 모델과 제출 결과를 만든 날이었다면, Day06은 **모델 결과를 근거로 추가 데이터를 탐색하고 피처의 의미와 중복 가능성을 검토한 날**이었다.
- 처음에는 매장 정보를 추가하면 도움이 될 것이라고 생각했지만, 작은 클러스터를 보면서 그 의미를 의심하고 교차표로 관계를 더 확인했다.
- 컬럼별 분포를 보는 것과 컬럼 간 관계를 보는 것은 서로 다른 질문에 답한다는 점을 체감했다.
- 병합 후에도 컬럼이 생겼다는 사실만 확인하지 않고, 결측치와 행 수를 점검해 데이터 연결을 검증했다.
- 한 줄 정리: **EDA는 발견 → 질문 → 추가 비교 → 활용 가설로 이어지며, 피처의 실제 가치는 같은 조건의 모델 실험으로 확인해야 한다.**

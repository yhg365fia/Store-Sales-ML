# Day21 실험 방식 회고

> **프로젝트:** Kaggle Store Sales – Time Series Forecasting
> **주제:** 실험 설계·검증 방식 점검 및 학습 방향 재정립
> **한 줄 요약:** "더 많은 실험"이 아니라 "적절한 실험 설계와 신뢰할 수 있는 결론"으로 초점을 옮기기로 한 날.

---

## 1. 오늘의 핵심

지금까지의 Store Sales 프로젝트 진행 과정과 내가 느낀 정체감을 바탕으로 현재 위치를 점검했다.

- 현재 수준: **초중급 ML → 중급 ML로 넘어가는 과도기**
- ML 기법을 사용하는 경험은 충분히 쌓이고 있다.
- 하지만 **상황에 맞게 선택하고, 결과를 신뢰성 있게 검증하는 능력**은 아직 발전 중이다.
- 정체감은 이 단계에서 자연스럽게 나타나는 현상이지만, **정체감 자체가 성장의 증거는 아니다.** 실패한 실험에서 판단 기준을 얻고 다음 실험 방식이 달라져야 실제 성장이다.

## 2. 현재 역량 평가

| 영역 | 평가 | 코멘트 |
|---|---|---|
| ML 개념 이해 | 초중급 | 다양한 모델과 피처 기법을 이해하고 활용 |
| 데이터 전처리 | 초중급 | 시계열 처리 및 외부 데이터 병합 경험 |
| 피처 엔지니어링 | 초중급 | Lag, Rolling, EMA 등 다양한 실험 |
| 검증 설계 | 초중급 | CV, Backtest의 목적은 이해하나 적용 판단이 미숙 |
| 실험 결과 해석 | 초중급 | 전체·그룹별 성능 분석 가능 |

| 실험 관리·중단 | 초급 | 개선이 없어도 반복 실험하는 경향 |

## 3. 회고 (KPT)

### Keep — 이어갈 것
- 다양한 모델링 접근을 시도하는 적극성
- Lag / Rolling / EMA 등 여러 피처 실험을 실제로 실행해 본 경험
- 전체·그룹별로 결과를 비교하고 해석하려는 습관

### Problem — 문제점

1. **지식의 체계화 부족**
   개별 기법은 알지만, 실제 문제에서 *어떤 기법을 언제* 써야 하는지 판단하기 어렵다.
2. **실험 설계의 불명확성**
   가설, 변경 변수, 기대 효과, 평가 기준을 정하지 않고 시작할 때가 있다.
3. **성능 개선 중심의 반복**
   CV나 리더보드 점수가 오르지 않으면 작업을 끝내기 어렵고, 실험 목적이 *가설 검증*에서 *점수 올리기*로 바뀌곤 한다.
4. **결과의 신뢰성 검토 부족**
   일부 Fold의 개선이나 작은 RMSLE 감소를 실제 일반화 성능 개선으로 받아들일 위험이 있다.
5. **중단·방향 전환의 어려움**
   효과가 미미한 피처나 모델을 반복 실험하며 시간과 에너지를 소모한다.

## 4. 개선 과제와 구체적 행동

| 개선 과제 | 구체적인 행동 |
|---|---|
| 가설 기반 실험 | 실험 전 기대 효과와 근거를 **한 문장**으로 작성 |
| 변수 통제 | 가능한 한 한 번에 **하나의 요소만** 변경 |
| 피처 관계 분석 | 단순 상관관계와 실제 예측 기여도를 구분 |
| 검증 방법 선택 | CV는 후보 비교, 독립 Backtest는 시간적 일반화 확인 |
| 결과 신뢰도 | Fold별 편차, 품목별 성능, 개선 규모 검토 |
| 실험 중단 | 시작 전에 채택·보류·중단 기준 설정 |
| 실험 기록 | 성공·실패 여부보다 **가설과 결론** 중심으로 기록 |
| 자기 판단력 | AI에 요청하기 전에 실험 방향과 이유를 직접 제시 |

## 5. 앞으로 사용할 실험 절차

1. **문제 정의** — 현재 모델의 문제점과 개선 목표 확인
2. **가설 수립** — 개선이 예상되는 이유와 데이터 근거 작성
3. **실험 설계** — 변수 통제, Baseline, 검증 방식, 중단 기준 결정
4. **실험 및 분석** — CV 결과, Fold별·그룹별 차이, 효과 크기 분석
5. **일반화 검증** — 선정한 후보를 독립적인 과거 기간에 검증
6. **결론 및 기록** — 채택 / 보류 / 폐기 결정, 다음 가설 정리

## 6. 실험 운영 원칙

- **횟수보다 정보 가치** — 왜 필요한 실험인지 설명할 수 있어야 한다.
- **성과와 학습 분리** — 점수가 나빠져도 가설에 대한 결론을 얻었다면 의미 있는 실험이다.
- **작은 개선을 의심** — Fold별 일관성과 독립 Backtest를 확인하고, 반복 실험에 따른 *검증 과적합*도 고려한다.
- **사전 중단 기준** — 비슷한 실패가 반복되면 파라미터만 바꾸지 말고 가설 자체를 재검토한다.
- **리더보드 의존 축소** — Public 점수는 참고만 하고, 모델 선정은 신뢰할 수 있는 로컬 검증 중심으로 한다.

## 7. 학습 방식에 대한 다짐

- 초기에는 새 기법을 배우고 구현하면서 성장이 빠르게 체감되지만, 이후에는 **실험의 타당성·신뢰도·일반화 가능성**을 판단하는 능력이 중요해진다.
- AI는 코드를 대신 써 주는 도구에 그치지 않고, **내 실험 설계의 허점을 검토하고 결과 해석을 반박하는 멘토**로 활용한다.
- 지금 필요한 것은 새로운 기법을 무작정 추가하는 것이 아니라, **쌓아 온 경험을 재사용할 수 있는 판단 체계로 만드는 것**이다.

## 9. 다음 2주 계획

**흐름:** 유가 데이터 실험 → 앙상블 실험 → 회고 정리

**공통 규칙:** 새로운 실험은 5장의 **사전 설계서를 작성한 경우에만** 진행한다. 한 번에 하나의 변수만 바꾼다.

### Phase 1. 유가 데이터 실험

**목적:** 외부 데이터(유가)가 예측 성능에 실제로 기여하는지 검증한다.

| # | 실험 | 가설 (작성 예정) | 변경 변수 |
|---|---|---|---|
| 1-1 | Baseline 확정 | 유가 없이 기준 성능을 고정한다 | 없음 |
| 1-2 | 유가 원본값 추가 | | 유가 원본 (결측 처리 포함) |
| 1-3 | 유가 파생 피처 추가 | | Lag / Rolling 등 |
| 1-4 | 품목군별 효과 확인 | | 품목군별 성능 비교 |

- [ ] 1-1~1-4 각각 사전 설계서 작성
- [ ] CV 결과 + Fold별 편차 + 품목별 차이 확인
- [ ] 독립 Backtest로 일반화 검증
- [ ] **중단 기준:** 1-2, 1-3 모두 Fold 간 일관된 개선이 없으면 유가 피처는 보류·폐기하고 가설 자체를 재검토
- [ ] 채택 / 보류 / 폐기 결정 및 기록

### Phase 2. 앙상블 실험

**목적:** 모델 조합이 단일 모델보다 안정적으로 나은지 검증한다.

| # | 실험 | 가설 (작성 예정) | 변경 변수 |
|---|---|---|---|
| 2-1 | 후보 모델 확정 | Phase 1 결과를 반영한 단일 모델을 고정한다 | 없음 |
| 2-2 | 단순 평균 앙상블 | | 조합 방식 |
| 2-3 | 가중 평균 앙상블 | | 가중치 |
| 2-4 | (선택) 스태킹 | | 메타 모델 |

- [ ] 각 실험 사전 설계서 작성
- [ ] 단일 모델 대비 개선 규모와 Fold별 일관성 확인
- [ ] 가중치 튜닝 횟수에 따른 **검증 과적합** 점검
- [ ] 독립 Backtest로 일반화 검증
- [ ] 채택 / 보류 / 폐기 결정 및 기록

### Phase 3. 회고 정리

**목적:** 쌓인 실험을 재사용할 수 있는 판단 체계로 정리한다.

- [ ] 기존 실험 **5개**를 선정한다.
- [ ] 각 실험을 **가설 · 변수 · 결과 · 신뢰도 · 일반화 · 최종 판단** 기준으로 재분석한다.
- [ ] Phase 1·2에서 얻은 결론을 같은 기준으로 기록한다.
- [ ] 반복되는 실수와 판단 기준을 정리한다.
